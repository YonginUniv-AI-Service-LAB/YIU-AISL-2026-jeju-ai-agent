## 2-2. 수집·전처리·분석 흐름

```
API (제주데이터허브 753·748, 공공데이터포털 ASOS)
 → data/raw/fetch/ : 응답 원본 저장(중간에 끊겨도 이어받기, 502 재시도)
 → data/snapshot/2026-08-31/*.parquet + manifest.json(파일별 sha256, snapshot_id eb593ba554a7)
 → 검증 게이트 6개 (하나라도 FAIL이면 중단)
 → 최근 6주 vs 직전 6주, 최근 6주 vs 전년 같은 기간(364일 전, 요일 맞춤), 강수일·비강수일 차이
 → 데이터 적합성 판정 F1~F7 (적합 / 범위 축소 / 판정 불가)
 → 진단 4유형 (동반 하락형 / 나만 하락형 / 계절·날씨형 / 판단 불가)
```

| 단계 | 내용 |
|---|---|
| 수집 | 기간 조회 + 페이지(`limit`·`number`). 제주데이터허브는 같은 요청에도 무작위 502가 있어 지수 대기 재시도. API 키는 `.env`에서만 읽고 로그·오류 메시지에서 가림 |
| 정리 | 원본을 parquet로 저장, 파일마다 sha256을 manifest에 기록. 원본이 바뀌면 해시가 달라져 드러남 |
| 검증 게이트 | ① manifest 해시 ② 필수 컬럼·자료형 ③ 비교 창 날짜 연속성(결측 최대 4일) ④ 시범 읍면동·관측소 존재 ⑤ 748 빠진 행·0값 비율(10% 이하) ⑥ 마지막 관측일 ↔ 기준일 지연 |
| 매칭 | 애월읍·노형동·연동 → ASOS 184(제주), 한림읍 → 185(고산) |
| 결측 | 빠진 날짜는 0으로 채우지 않고 계산에서 제외. 748 빈칸이 10%를 넘으면 외국인 지표만 숨김(F6). ASOS 강수량 빈값은 무강수(0mm)로 처리 |
| 라이브 모드 | 점주 기록의 마지막 주를 기준일로 그 읍면동·기간만 조회, 같은 형식의 스냅샷(manifest·snapshot_id)으로 저장해 재현 가능. 실패 시 기준일 스냅샷으로 대체하고 사유 표시 |

## 2-3. 쓰지 않는 해석
- 읍면동 유동인구를 "매장 방문객", "반경 500m 유동인구", "고유 방문자 수"로 부르지 않습니다(읍면동 단위 일 합계).
- 방문인구 전체를 "관광객"으로, 748을 "외국인 관광객 수"로 부르지 않습니다(외국인 단기체류 유동인구).
- 동시에 나타난 변화를 원인으로 단정하지 않습니다(원인 후보로만 제시).
- 리포트 검증 단계가 위 표현을 자동으로 검사합니다.

## 2-4. 데이터 보관
- 기준일 스냅샷(`data/snapshot/2026-08-31/`)과 라이브 동결 데이터(`data/live/snapshots/노형동_2026-06-28/`, snapshot_id `be4aa6c54a63`)는 **제출 ZIP에만** 포함하고 GitHub에는 올리지 않습니다.
- 데이터 API 키, `.env`, 원본 응답(`data/raw/`), 라이브 캐시(`data/live/cache/`)는 제출물에 넣지 않습니다.
- 개인정보: 점주 질문 원문은 저장하지 않고, 재방문 세션에는 지역 코드·진단·추천 실험·시작일만 저장합니다.
